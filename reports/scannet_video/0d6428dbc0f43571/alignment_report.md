# ScanNet 多帧对齐实现与首轮结果

日期：2026-09-11

实验编号：`0d6428dbc0f43571`

后续多帧 B15 通道剪枝已完成，见[剪枝实验报告](../../scannet_channels/3581b90dbd488ff0/technical_report.md)。本页保留首轮未剪枝的提取与测量结果。

## 1. 已完成的改动

新增多帧入口 `scripts.scannet.video_scan`。它直接使用前面点跟踪和 OVIS 所用的本地 `WanPipeline`、`WAN_2_1` 配置及 HEFT 的分块、输入预处理和 Q/K 捕获接口。旧单帧入口继续作为独立对照。

本次完整运行覆盖五个 ScanNet 场景，每景 32 张原有采样帧，扫描 B14/B15 的完整 hidden 和每层全部 12 个注意力头，分别评价 KK、QK。共 50 个候选、7750 条原始帧对评分。

实际检查到十个片段、二十次条件/无条件 Transformer 前向，输入均为 `[1,16,25,60,104]`。经过 patch embedding 后，每段是 `[1,39000,1536]` 的联合时空 token 序列。时间维不是独立图像的 batch 维。

## 2. 对齐了什么

| 项目 | 旧 ScanNet 单帧 | 本次多帧 |
|---|---|---|
| Transformer 上下文 | 每个样本 1 帧 | 每个片段 25 帧，联合时空注意力 |
| VAE 输入 | 每帧分别编码 | 整个视频片段编码，保留因果卷积上下文 |
| VAE 时间下采样 | HEFT 已关闭 | 保持相同本地 VAE 结构 |
| VAE latent | float32 编码，取 mode | HEFT 视频路径的 bf16 和 sampling |
| 调度器 | VEGA 参考的 1000 步、shift=5 | checkpoint 的 UniPC、50 步、flow_shift=3 |
| 提取位置 | 请求 k=300，实际 timestep 299 | HEFT 的 step index 49，实际 timestep 57 |
| sigma | 0.299923837 | 0.057636831 |
| 文本 | 空文本 | 空文本，guidance scale 5，仅捕获条件分支 |
| 图像大小 | 480×832 | 480×832 |
| 评分网格 | 14×14 | 14×14，逐帧空间池化 |
| 采样与几何 | 每场景均匀采样 32 帧 | 沿用完全相同的帧编号和几何真值 |

需要纠正旧说明中的一处用词：HEFT 关闭的是 VAE 的时间下采样，并没有关闭编码器内所有时间卷积。单帧与视频 VAE 的上下文确实不同。

每个场景的前 25 张采样图像组成第一个片段，剩余 7 张组成第二个片段，重复最后一张 RGB 补到 25 张。这沿用 OVIS 的尾段补齐策略；原点跟踪脚本默认丢弃不足一段的尾帧。补齐图像参与模型上下文，但补齐位置的描述子不进入评分。

本轮对齐的是编码方式和模型设置。ScanNet 仍使用原来的稀疏采样序列，并未变成 25 张原始连续帧；原始帧间隔及时间戳均保留。三种任务的下游指标也没有被混成同一指标。

## 3. 如何保证帧与指标对应

- Q/K 使用原有 `AttentionFeatureCapture`，只读取条件分支的归一化和 RoPE 后张量。
- 完整 hidden 使用 block 输出 hook，不以某个头的输出代替整个 block。
- 恢复 token 的时间、空间次序后，对每帧独立做 float32 空间池化。
- 每个场景最终 hidden 为 `[32,1536,14,14]`，Q/K 为 `[32,12,128,14,14]`。
- 每帧只采用所属片段的一份特征；跨场景不共享上下文，跨片段也没有额外注意力连接。
- 余弦、QK 缩放点积、全部有效目标检索、分数化并列、缺失帧对处理和场景等权均复用原来的三维评分实现。

报告同时提供两个帧对子集：

| 口径 | 帧对数 | 有共享体素的帧对数 | 含义 |
|---|---:|---:|---|
| all_pairs | 155 | 144 | 保留所有相邻采样帧对，与旧主结果覆盖一致 |
| within_chunk | 150 | 139 | 去掉每景一对跨片段边界的帧对 |

与旧单帧结果比较 `within_chunk` 时，旧结果也取完全相同的 150 对子集；这不表示旧特征也拥有联合上下文。7750 条候选评分的几何覆盖和缺失状态均与原始对应帧对一致。

| B15 hidden，1536 维 | 旧单帧 | 28.912 | 43.433 | 0.2760 |

| B15 H2 KK，128 维 | 旧单帧 | 23.647 | 35.015 | 0.3921 |
| B15 H2 KK，128 维 | 新多帧 | 26.921 | 38.099 | 0.3929 |

## 5. 验证与结论范围

- 38 项测试通过，包括真实小型 Wan Transformer 的上下文扰动、捕获不改变原前向、条件/无条件分支区分、时间次序、尾段裁剪、异常后 hook 恢复、边界帧对汇总和多帧通道缓存读取。
- 实际权重运行完成五场景、十个片段；二十次 Transformer 前向均保持 25 帧时间维。
- 原始帧编号、有效 token 数、共享体素数和每个候选的评分覆盖保持一致。
- 运行记录中的提取、几何、评分与共享 HEFT 源文件哈希均与执行版本一致。见 [对齐检查记录](alignment_audit.json)。
- 通道筛选入口读取新 B15 缓存后，完整复算 155 个帧对，七项原有指标的最大差值均为零。见 [基线复核](video_hidden_baseline_check.json)。

本次完整提取与评分约 413.03 秒，PyTorch 峰值已分配 GPU 内存约 13.53 GiB。该值不是设备总占用，也不是与旧实验严格受控的性能基准。

结果支持把三维任务纳入多帧编码条件下重新评价各头，但不支持“多帧必然全面提高指标”的说法。与旧结果相比，VAE 上下文、latent 取样方式、精度和噪声配置同时变化；尚未执行相同新调度下的单帧控制实验，因此不能把所有差异归因于 Transformer 的时间交互。

旧的 384 维方案仍是单帧设置下的结果。新的 hidden 和通道筛选接口已经接通，但本轮没有在多帧特征上重新选择或验证 384/256 维通道表。

## 6. 运行入口

在仓库根目录设置 [ScanNet 说明](../../../scripts/scannet/README.md) 中的源码路径和离线环境变量后执行：

```bash
.venv/bin/python -m scripts.scannet.video_scan --device cuda:4 --no-previews

.venv/bin/python -m scripts.scannet.channel_scan \
  --baseline-run ../eval/scannet_video/0d6428dbc0f43571 \
  --timestep 49 --baseline-only --device cpu
```

更改设备或配置会生成不同运行编号。`video_scan --chunk-size 1` 可以运行同一 HEFT 模型配置的单帧控制实验；其他视频长度需满足本地 VAE 的 `4n+1` 输入限制。

实现文件：[视频提取](../../../scripts/scannet/video_extract.py)、[扫描入口](../../../scripts/scannet/video_scan.py)、[评分汇总](../../../scripts/scannet/video_report.py)、[验证测试](../../../scripts/scannet/test_video.py)。
